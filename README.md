我把历代设计大师的内核全蒸馏了一遍。

画风各不相同，蒸到最后，居然只剩同一个参数。现已重磅开源，参数就在标题里。

## 半小时能打包一套画风，审美呢？

最近刷设计内容，经常看到有人把画风做成 Skill。配色、笔触、材质和光线，整理成一套预设，做系列封面确实省事。愿意拿出来分享，也是好事。

可到了发布帖里，怎么就从「这套预设挺好用」，变成了「装上它，你也能拥有我的审美」？再经过几轮自媒体吹捧，仿佛设计师的经验、判断和品味，都能靠一条安装命令传给别人。

分享画风没问题。但把预设包装成审美，把安装量变成个人能力的证明，这中间是不是省略了太多东西？

几张漂亮的样图，能展示一种效果，却回答不了它为什么适合眼前的问题。做一本展览手册，一张插画再漂亮，如果抢了作品的注意力，要不要删掉？预设能继续生成，决定却还是得有人来做。

AI 越来越擅长一次给出十张好看的图。这时候更重要的，是你知道为什么选其中一张，或者为什么十张都不想用。

如果连「什么是好的」也总由同一套预设、同一批推荐替你决定，时间久了，还分得清什么是自己喜欢的，什么只是看惯了的吗？

**AI 时代，个人品味更值得培养。它不该成为安装工具时，顺手交出去的东西。**

## 我更想把时间花在基础设施上

半小时可以打包一套画风。真要投入接下来的几周、几个月，我更愿意把时间花在设计工具的基础设施上。

不少设计师和设计工程师已经在做这样的事：

- **枯白 · [Glasswork](https://www.kubai.design/glasswork/)**  
  把液态玻璃效果做成可以调参数、换背景、复制 CSS 的工具。你可以从他的效果出发，继续调整到适合自己的设计。

- **Emil Kowalski · [Vaul](https://vaul.emilkowal.ski/)**  
  把抽屉的拖动、关闭等交互做好，把视觉样式留给使用者。交互经验可以复用，界面仍然可以有自己的样子。

- **Paco Coursey · [cmdk](https://cmdk.paco.me/)**  
  提供可组合、无预设样式的命令菜单，让设计师和开发者根据自己的产品组织功能与表达。

- **Rauno Freiberg · [inspx](https://github.com/raunofreiberg/inspx)**  
  让设计师直接检查页面里的布局尺寸，帮助核对设计在实际页面中的呈现。

这些工具当然带着作者的经验，甚至能看出作者的品味。但它们给使用者留下了继续设计的空间：可以拆，可以改，也可以做出作者没想到的东西。

我理解的「授人以渔」，就是给人继续尝试的条件。工具越好用，使用者越有机会走到自己的答案。

这也是我关注 DeepSeek Harness（DSH）里这些插件的原因：

- **[DSH × Blender](https://github.com/sixtysevenlf/dsh-blender-plugin)**：让模型参与 Blender 中的修改，通过出图对照，支持设计师继续推敲形体、材质和光线。
- **[DSH × ComfyUI](https://github.com/fandc520/dsh-comfyui)**：连接已有的图像工作流，让设计师更方便地调整参数、尝试不同效果。

这些都是给设计师使用的工具。它们的价值，应该体现在设计师能不能更方便地尝试、修改和完成自己的设计。

短流程 Skill、项目规则，我一样会写。但当模型已经知道怎么做，却读不到文件、操作不了工具、改完看不到结果时，把这些环节接起来，对我更有意义。

设计师手里往往已经有一份稿，也有自己的主意。有时缺的，只是让那个「改起来太麻烦，先算了」的想法，终于有机会被试出来。

## 给设计师留一点「自负」的空间

我不想教设计师怎么设计。

做设计的人，多少都有一点「自负」。相信自己的审美，有不愿轻易退让的坚持，也有一些还没做出来、但很想证明的想法。我也一样。

说到底，这里面就是一个人的品味：你看重什么，愿意舍弃什么，为什么明明有现成的答案，还是想试试自己的那一版。

这些判断未必每次都对。但亲手做出来，摆在一起看，发现值得坚持，或者承认应该改主意，都是形成自己品味的过程。没有哪个 Skill 能替你经历。

我更希望工具能省下那些重复操作，让设计师有精力把自己的判断做充分。多试一种可能，多推敲一次细节，把一直放在心里的东西真正做出来。

至于这个号称蒸馏了历代大师的 Skill，它还真有一个 [SKILL.md](skills/duoasa-skill/SKILL.md)。里面没有大师的统一画风，只有一套协作约定：从你的想法出发，把选择和取舍讲清楚，帮你把想做的东西做出来。

**这个 Skill 会让模型帮你做自己。**

如果你读到了这里，那么你自己就已经装上了这个 Skill。希望在 AI 时代，你能少一点盲目跟随，借助 AI，把自己真正想做的东西做出来。

<summary>想给模型也装上？展开安装与使用说明</summary>

真正的 Skill 文件在 [skills/duoasa-skill/SKILL.md](skills/duoasa-skill/SKILL.md)。把 `duoasa-skill` 文件夹放进客户端支持的 Skills 目录即可；仅下载仓库不会自动启用。

先下载仓库（以下命令适用于 macOS、Linux 或 Git Bash）：

```bash
git clone https://github.com/Duoasa/Duoasa-skill.git
cd Duoasa-skill
```

按使用的客户端选择一组命令：

**Codex**

```bash
mkdir -p "$HOME/.agents/skills"
cp -R -i skills/duoasa-skill "$HOME/.agents/skills/"
```

在对话中调用：

```text
$duoasa-skill 根据我已有的稿件和偏好，帮我把这个方向继续做下去。
```

**Claude Code（本地）**

```bash
mkdir -p "$HOME/.claude/skills"
cp -R -i skills/duoasa-skill "$HOME/.claude/skills/"
```

在对话中调用：

```text
/duoasa-skill 根据我已有的稿件和偏好，帮我把这个方向继续做下去。
```

安装位置依据 [Codex 文档](https://learn.chatgpt.com/docs/build-skills)与 [Claude Code 文档](https://code.claude.com/docs/en/skills)。若当前会话未显示新 Skill，重新打开会话后再选择。其他支持 Agent Skills 的客户端，请按其安装说明导入同一文件夹；不支持 Skills 的聊天工具，也可以直接阅读并引用文件内容，但这不等于安装。

它会引导模型从你的目标、稿件和偏好出发，解释取舍、帮助试做，减少重复操作。它不提供统一画风，也不承诺让人一键拥有审美。
